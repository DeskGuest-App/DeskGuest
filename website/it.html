Architecture in one paragraph

No DeskGuest cloud and no DeskGuest account: identity is a key held on the device, with a recovery key (Windows) or a 34-word recovery key sheet (Android) as the only way back in — there is no central reset. Devices pair with one-time codes (10-minute expiry, single use). Some connection paths use a third-party coordination service (for example Tailscale) for device discovery only; it never holds sessions or records.

Consent floor — not configurable

Presence (the connected helper, human or AI agent, is named on the helped person's screen and everything they do is visible); STOP, which halts a session instantly from the on-screen button or Ctrl+Alt+Shift+F9; control that changes hands only through explicit Give control / Take control, so moving the mouse or typing never takes it back; and an Activity Record that can't be quietly edited are properties of the product, not settings. Policy governs comfort and scope — it cannot switch the floor off. Unattended access is no exception: it runs only under a standing grant the owner created in advance, and presence, STOP, and the record apply to it in full.

Policy & Effective Policy

Rules are written as sentences with scope and source, inherited workplace → group → device. The Effective Policy view shows the resolved result for a given device ("what actually applies"), not just the rule stack. Camera viewing, patch approvals, and automatic fixes are governed by policy and written into the record; patch rollouts need an approval first and stop themselves if anything goes wrong.

Records & exports

The Activity Record lives on the device and accounts for what DeskGuest itself did — what was looked at, sent, and changed. Exports are local files (including CSV) produced on the device. Backups go to storage you own. Compliance evidence packs list their contents before export.

Compliance, answered honestly

DeskGuest has no SOC 2, ISO 27001 or other third-party certification or attestation, and makes no HIPAA compliance claim. DeskGuest runs no cloud, keeps no account database and collects no telemetry. Session records stay on your devices. If your organization requires a certified or attested vendor, DeskGuest does not meet that requirement today.

Deployment shapes

Standalone per device, or a workplace hub run once by the organization with sites enrolling by code. There is no DeskGuest-imposed user limit and no device limit. Offboarding is one removal action with the blast list shown first; removing a fellow admin takes dual control, and the last admin cannot be removed.

Security disclosure

Report vulnerabilities privately via GitHub private vulnerability reporting on the DeskGuest project: open a private security advisory. When DeskGuest is publicly released, downloads and the File Check Code (SHA-256) for each will be published only on the DeskGuest releases page on GitHub. There is no public release yet. No GitHub account? Email support@deskguest.app with "Security report" in the subject.

AI agents and your data

Only inside a session you granted

An AI agent sees a device's data only during a live session, under the access its pairing was granted, with its presence shown on screen the whole time. There is no background feed and no access outside the sessions and grants the owner has given.

If the agent runs in a cloud, that is where shown data goes

Some agents run on their provider's servers. Anything such an agent is shown in a session — screen contents, files it opens — travels to that provider to be processed. No software can show a cloud agent your screen and keep that screen off the provider's machines at the same time. Choosing the agent is choosing where session data can go.

An agent that runs locally keeps data local

If you pair an agent that runs on your own hardware, on the device itself or a server you operate, DeskGuest sends session data only to that agent. Whether the agent sends data anywhere else depends on the agent. DeskGuest works the same either way, and the owner chooses which agents to pair.

What DeskGuest itself guarantees

Access is per pairing and per grant: the owner decides what each agent may see and do, sensitive actions can require approval on the device itself, and STOP ends any session at once. The Activity Record counts what each agent was shown — every item, every byte — so what an agent saw is a written record, not a guess. And DeskGuest runs no cloud and collects no telemetry of its own: the vendor sees none of it.
